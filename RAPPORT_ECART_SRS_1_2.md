# Madrassa — état d'application du SRS 1.2

Analyse du 11 octobre 2026, mise à jour les 12 et 13 octobre avec les incréments 14 à 41. Référence : `SRS_Madrassa_1_2.md`, décisions §10.1 et rapport 1.1 déjà intégré. La suite reprend le plan existant ; aucune nouvelle décision d'architecture n'est introduite. Le document SRS source n'est pas modifié.

## Base retenue et preuves

`platform/` est la nouvelle application normative (ND-09) : Laravel 12, Filament 5, PostgreSQL, schéma incrémental, rôles SQL restreints, API et services. `ecole-filament/` et `madrassa-backend/` restent l'application antérieure ; leur couverture ne vaut pas conformité de la nouvelle base. Les bulletins et la démonstration sont hors périmètre (ND-02, ND-04).

Validation de l'incrément 41 : 222 tests PHP/PostgreSQL 16 (7 326 assertions) ; 197 contrôles SQL embarqués et 211 sur PostgreSQL 16 natif, dont deux ajouts simultanés d'une même matière à un programme ; migration 028 annulée seule avec des matières, leurs versions et un paramètre d'école en place, puis avec toutes les autres, et réappliquée ; recette navigateur locale dans Chromium : 140 écrans sans problème, matières d'un programme comprises ; Firefox et WebKit par la CI. Incrément 40 : 220 tests PHP/PostgreSQL 16 (7 040 assertions) ; 192 contrôles SQL embarqués et 205 sur PostgreSQL 16 natif, dont deux retraits simultanés de contacts principaux et deux transferts simultanés de même clé ; migration 027 annulée seule avec des transferts en place, puis avec toutes les autres, et réappliquée ; recette navigateur laissée à la CI (une action et une section d'historique de plus sur l'écran Inscriptions). Incrément 39 : 217 tests PHP/PostgreSQL 16 (6 917 assertions), dont NameMatchTest (clé de recherche identique à celle de la base, noms algériens dans les deux alphabets), DuplicatesTest, le responsable ressaisi sur la fiche élève (SchoolingPanelTest) et à l'import (PupilImportTest) ; aucune migration, contrôles SQL et écrans inchangés (les avertissements apparaissent dans les formulaires). Incrément 38 : 209 tests PHP/PostgreSQL 16 (6 728 assertions), dont la photo de l'élève par l'API (StudentPhotoTest) et par la fiche (SchoolingPanelTest) ; 190 contrôles SQL embarqués et 201 sur PostgreSQL 16 natif ; migration 026, retour arrière complet puis de 026 seule avec des photos en place, et réapplication validés ; recette navigateur locale dans Chromium : 136 écrans sans problème, la fiche élève avec sa photo, chaque image vérifiée chargée ; Firefox et WebKit par la CI. Incrément 37 : 203 tests PHP/PostgreSQL 16 (6 479 assertions), dont l'import des 500 élèves de référence avec leurs responsables et inscriptions (sortie du lot 2) ; 186 contrôles SQL embarqués et 197 sur PostgreSQL 16 natif ; migration 025, retour arrière complet et réapplication validés ; recette navigateur non rejouée (aucun écran nouveau, l'écran Imports propose trois sortes de plus, vérifié par SchoolServicesPanelTest). Incrément 36 : parcours du lot 2 par les seuls écrans ; migration 024 ; recette navigateur de 136 écrans par navigateur (fiche élève et élèves d'une classe compris). Incrément 33 : migration 023, droits restreints, retour arrière et réapplication validés ; coût des portées mesuré par `platform/tests/sql/scope-cost.mjs`. Les incréments 30 à 32 ont été versés ensemble sur `main` et vérifiés par la CI complète (contrôles SQL natifs, tests PHP, retour arrière, déploiement, sauvegarde restaurée, recette des 324 écrans). Les preuves de l'incrément 29 restent acquises : 108 écrans dans chacun des navigateurs Chromium, Firefox et WebKit, en français et en arabe, ordinateur et téléphone (`platform/deploy/acceptance-test.sh`) ; déploiement Docker Compose (`platform/deploy/smoke-test.sh`) et sauvegarde chiffrée restaurée dans une installation neuve (`platform/deploy/restore-test.sh`), en CI. La revue de sécurité du lot 1 est dans `platform/SECURITY-REVIEW.md`. Les tests utilisent des bases jetables, jamais les données de l'application antérieure. « PARTIEL » peut désigner un schéma ou une API testés sans parcours utilisateur ; aucune ligne n'affirme la conformité complète du produit avant recette.

Abréviations de fichiers : **SQL** = `platform/database/schema/`, **API** = `platform/app/Http/Controllers/`, **services** = `platform/app/Support/`, **tests** = `platform/tests/Feature/` et `platform/tests/sql/`, **UI** = `platform/app/Filament/`, **CI** = `.github/workflows/ci.yml`. S/M/L : effort relatif d'un complément, pas un engagement calendaire.
